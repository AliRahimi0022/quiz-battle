# کوییز کلاب

[English](README.md)

یک مسابقهٔ دو نفره که روی سیستم خودت اجرا می‌شه. یک نفر اتاق می‌سازد، لینک دعوت را می‌فرستد، و هر دو نفر به نوبت به سؤال‌های یکسان جواب می‌دهند. جواب درست ۱۰ امتیاز دارد و اگر در نیمهٔ اول زمان ۳۰ ثانیه‌ای ثبت شود، ۳ امتیاز اضافه هم می‌گیرد.

## پیش‌نیاز

- پایتون ۳.۱۰ یا جدیدتر

## اجرا

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

کلید Gemini را در فایل `.env` در ریشهٔ پروژه قرار دهید:

```env
GEMINI_API_KEY=کلید-google-ai-studio-خودتان
```

سپس برنامه را اجرا کنید:

```bash
python app.py
```

بعد[http://127.0.0.1:5000](http://127.0.0.1:5000) را باز کنید.

| متغیر | پیش‌فرض | کاربرد |
|---|---|---|
| `HOST` | `127.0.0.1` | آدرسی که سرور روی آن گوش می‌دهد |
| `PORT` | `5000` | درگاه سرور |
| `SECRET_KEY` | یک مقدار مخصوص توسعهٔ محلی | کوکی نشست را امضا می‌کند. پیش از اینکه سرور را با دیگران به اشتراک بگذارید این مقدار را عوض کنید. |
| `GEMINI_API_KEY` | تنظیم‌نشده | کلید اختیاری Google Gemini، از متغیر محیطی یا فایل `.env` بارگذاری می‌شود. اگر تنظیم شود، برای هر اتاق تازه پنج سؤال تولید می‌شود و مربی به سؤال‌های راند پاسخ می‌دهد؛ در غیر این صورت از بانک محلی استفاده می‌شود و مربی در دسترس نیست. |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | مدل Gemini برای تولید سؤال و پاسخ مربی |
| `APP_DEBUG` | تنظیم نشده | اگر `1` باشد، با تغییر کد سرور دوباره بارگذاری می‌شود. |

## بازی

1. اسمتان را وارد کنید و یک اتاق بسازید.
2. لینک اینوایت را برای بازیکن دیگر بفرستید. اسم او باید با اسم شما فرق داشته باشد.
3. هر دو نفر آماده را بزنند. مسابقه با نوبت میزبان شروع می‌شود.
4. پیش از تمام شدن زمان، یکی از گزینه‌های A تا D را انتخاب کنید. بعد نوبت به بازیکن دیگر می‌رسد.
5. وقتی هر دو جواب دادند، نتیجهٔ دور را ببینید، دربارهٔ پاسخ یا امتیازتان از مربی بپرسید و با هم ادامه دهید.
6. با تمام شدن سؤال‌ها، صفحهٔ نتایج برنده را نشان می‌دهد. در تساوی برنده‌ای اعلام نمی‌شود.

بردها و مجموع امتیازها در تالار مشاهیر صفحهٔ اصلی نگه داشته می‌شوند. اول تعداد برد ملاک است، بعد امتیاز.

اگر `GEMINI_API_KEY` تنظیم شده باشد، برای هر اتاق تازه پنج سؤال انگلیسی جدید با Gemini ساخته می‌شود. اگر کلید موجود نباشد یا درخواست API شکست بخورد، از پنج سؤال محلی `questions.json` استفاده می‌شود.

بعد از پاسخ هر دو بازیکن، مربی ابتدا نام بازیکن واردشده به مسابقه را می‌پرسد. سپس می‌تواند با استفاده از سؤال جاری، گزینه‌ها و پاسخ درست، جواب‌های هر دو بازیکن و امتیازهایشان پاسخ دهد. سؤال‌های بعدی، تاریخچهٔ گفتگوی بازیکنان و اطلاعات پایگاه‌داده در اختیار مربی قرار نمی‌گیرد. پاسخ مربی به `GEMINI_API_KEY` نیاز دارد.

## نمونهٔ agent

برای اجرای نمونهٔ agent که می‌تواند زمان جاری را نشان دهد یا یک تاس شش‌وجهی بیندازد:

مقادیر زیر را در فایل `.env` در ریشهٔ پروژه قرار دهید:

```env
GEMINI_API_KEY=کلید-google-ai-studio-خودتان
# GEMINI_MODEL=gemini-3.5-flash-lite
```

سپس اجرا کنید:

```bash
python agent_demo.py
```

درخواست خود را وارد کنید؛ مثلاً «زمان الان را بگو و یک تاس بینداز». مدل برای انجام این کارها از دو ابزار محلی استفاده می‌کند.
نام ابزارهای اجراشده و نتیجهٔ آن‌ها در ترمینال نمایش داده می‌شود و در فایل `agent_demo.log` هم ذخیره می‌شود.

## ساختار

| مسیر | نقش |
|---|---|
| `app.py` | مسیرهای FastAPI: اتاق، نوبت، گفتگو، نتایج |
| `coach.py` | پاسخ‌های جمینای بر اساس اطلاعات سؤال جاری |
| `agent_demo.py` | نمونهٔ agent جمینای با ابزار زمان جاری و تاس |
| `engine.py` | قانون امتیاز (`Question`، `Match`، `Chat`) |
| `storage.py` | بانک سؤال، جدول امتیاز JSON، ثبت جواب‌ها در SQLite |
| `templates/` | صفحه‌های خانه، پیوستن، بازی و نتایج |
| `questions.json` | سؤال‌ها، چهار گزینه، و حرف گزینهٔ درست |
| `tests/` | تست موتور، ذخیره‌سازی و جریان وب |

اتاق‌های فعال فقط در حافظه هستند و با توقف برنامه از بین می‌روند. مسابقه‌های تمام‌شده همچنان `leaderboard.json` را به‌روز می‌کنند و هر جواب در `quiz.db` نوشته می‌شود. هر دو فایل در اولین استفاده ساخته می‌شوند و در گیت نادیده گرفته شده‌اند.
